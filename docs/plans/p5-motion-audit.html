P5 motion and design audit

Branch fa-upgrade, 2026-10-11. Lens: Emil Kowalski primary (frequent actions get little or no motion), Jakub Krehel secondary, Jhey Tompkins only for empty states. Approved decisions (Calm Ledger teal, Manrope, outline+dot chips, A to Z categories, day/night follows phone) are not questioned. Items fixed after the P4 audit are not repeated. Read-only audit; no source was changed.

Summary

4 high9 medium8 low

Overall the new screens are restrained: only transform and opacity animate, the segment pill and FAB are right-sized, reduced motion is honoured app-wide (MotionConfig plus the CSS guard). The problems are keyboard-driven motion, sheets that cannot animate out, and a few state bugs in swipe-delete.

High

highEdit sheet has no exit animation

src/components/fa/TxEditSheet.tsx:32 (same pattern: src/pages/fa/Categories.tsx:89-90)

if (!tx) return null unmounts the whole Drawer the instant onClose runs, so the sheet vanishes instead of sliding away. This is the most frequent sheet in the app (Activity, Stats, swipe-right edit). Categories has the milder form: {editing && ...} and the title read editing?.from, so the form blanks and the title flips to "New category" while vaul is still closing.

Fix: remember the last value and keep rendering it while closed.

// TxEditSheet: replace line 32
const last = useRef(tx); if (tx) last.current = tx;
const cur = tx ?? last.current;
if (!cur) return null;           // only before the first open
// ...then use `cur` instead of `tx` in the body; keep open={!!tx}

// Categories: same idea
const lastEd = useRef(editing); if (editing) lastEd.current = editing;
const ed = editing ?? lastEd.current;   // render the form and title from `ed`; open={!!editing}

highActivity list animates on every keystroke, filter change and "Show more"

src/pages/fa/Activity.tsx:66, 90, 94 and src/components/fa/motion.tsx:40-44

Every row is a layout="position" motion node (up to 150) and enters with opacity, y and filter: blur(2px). Typing in search or toggling a filter re-enters and exits dozens of rows (keyboard-initiated, so it should never animate), "Show more" fires 150 blur enters at once, and the blur is a paint-heavy filter on a phone. The exit also leaves a 150 ms empty gap before siblings slide up after a swipe-delete.

Fix: animate only genuinely new rows and deletes; swap the list instantly on filter/range change; collapse height on delete.

// motion.tsx
export const listItem = {
  initial: { opacity: 0, y: 6 },                       // blur removed
  animate: { opacity: 1, y: 0, transition: { duration: 0.2, ease: EASE_OUT } },
  exit: { opacity: 0, height: 0, transition: { duration: 0.18, ease: [0.4, 0, 1, 1] } },
};

// Activity.tsx row()
<motion.div key={t.sn} layout="position" className="overflow-hidden"
  {...listItem} initial={fresh.has(t.sn) ? listItem.initial : false}>

// both AnimatePresence blocks: remount on filter/range change so nothing animates then
const listKey = JSON.stringify([filter, range]);
<AnimatePresence initial={false} key={listKey}> ...

Optional: drop layout="position" when view.shown.length > 60 (measuring 150 nodes on each render is the main jank source on search typing).

highSwipe-delete loses callbacks when two rows are deleted within 4.5 s

src/hooks/useSwipeDelete.ts:20-23

del is one shared mutation. TanStack Query only fires the per-call onError/onSettled of the latest mutate(). Delete row A, then row B within the undo window: A's callbacks are dropped, so if A fails it stays hidden with no error toast and no unhide (ghost state until reload). Callbacks are also dropped if the user leaves Activity before the timer fires.

Fix: use the promise API, which is per call.

const timer = setTimeout(() => {
  if (undone) return;
  del.mutateAsync(tx.sn)
    .catch(() => toast.error("Couldn't delete. Try again."))
    .finally(() => unhide(tx.sn));
}, UNDO_MS);

Note: .finally(unhide) after an error is correct (row returns); after success the optimistic cache update already removed it.

highSegment switch double-flashes: exiting page renders the new route

src/components/fa/AppShell.tsx:81-87

<Outlet /> inside AnimatePresence mode="wait" reads the current route context, so the exiting wrapper fades out showing the new page, then the new page fades in again. Segment switching is the highest-frequency navigation in the app.

Fix: freeze the outlet element per render.

import { useOutlet } from 'react-router-dom';
const outlet = useOutlet();
// ...
<motion.div key={loc.pathname} ...>{outlet}</motion.div>

Also consider dropping mode="wait" (exit 80 ms plus enter 150 ms in series delays content): use exit={{ opacity: 0, transition: { duration: 0 } }} or no exit at all.

mediumProgress bars slide for 600 ms while typing a budget

src/components/fa/motion.tsx:34 used at src/pages/fa/Budgets.tsx:92 and Stats.tsx:159

Typing in the budget field retargets the bar on each keystroke with a 0.6 s ease (keyboard-initiated, should be instant), and the colour changes instantly while the bar lags. The same 0.6 s applies when merchants re-sort on Stats (over Emil's 300 ms ceiling).

const mounted = useRef(false); useEffect(() => { mounted.current = true; }, []);
transition={{ duration: intro && !mounted.current ? 0.5 : 0.12, ease: EASE_OUT }}

mediumSwipe-left delete triggers on velocity alone

src/components/fa/SwipeRow.tsx:15

vx < -700 with any offset deletes the row, so a quick sideways flick while scrolling can delete (Undo exists, but a wrong delete plus 4.5 s toast is noisy). Same for the 70 px edit.

if (dx < -DELETE_AT || (vx < -700 && dx < -40)) { ... }
if (dx > EDIT_AT || (vx > 700 && dx > 40)) onEdit();

Delete is also reachable without gestures through the edit sheet, so the a11y path is fine.

mediumiOS zooms the page when a per-category budget field is focused

src/pages/fa/Budgets.tsx:97

The input is text-sm (14 px); iOS Safari zooms on focus below 16 px, and the viewport meta allows it. The shared Input is already text-base.

className="h-10 w-[84px] ... text-base font-bold ..."   // was text-sm; widen to w-[92px] if needed

mediumSelected chip text fails contrast on several palette colours

src/components/fa/CategoryChips.tsx:7-9

White 12 px bold on #E0719E, #1F9E89, #B5803A, #D96B4F, #3B8FB0 is roughly 2.8 to 3.8:1 (needs 4.5:1). Keeps the approved "filled when selected" style.

style={{ borderColor: cat.color, ...(on ? { background: `color-mix(in srgb, ${cat.color} 72%, black)` } : {}) }}

Also: chips are about 30 px tall; use py-2 for a 34 px target (gap-2 already separates them).

Working well

  • Only transform/opacity animate; Bar uses scaleX; CountUp animates only on real value change; recharts respects useReducedMotion.
  • Springs have bounce: 0; FAB press is 0.95; drag release uses a no-bounce spring.
  • Swipe row: direction lock, colour layers fade with drag distance, undo window with optimistic hide and an error path. Delete also lives in the edit sheet.
  • Reduced motion is covered twice (MotionConfig and the CSS guard); the settings Version, theme and install rows have no stray motion.
  • Save bar enter/exit is 200 ms transform plus opacity, appropriate for an occasional action.
